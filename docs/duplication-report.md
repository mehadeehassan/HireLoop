- Worktree caveat: frontend is clean on `refactor/dedupe`. The sibling backend remains on `refactor/mvc`, 40 commits ahead, with numerous pre-existing modified, deleted, and untracked files. It was scanned read-only and was not switched or edited; backend clusters need re-check against a clean, agreed backend baseline before any change.

## Intentional Duplicates to Retain

- Seeker, recruiter, and admin API routes/proxies: their role, actor source, ownership rules, response validators, and status/error mapping differ. Similar code does not make their security boundary interchangeable.
- Seeker and recruiter billing: plan quota fields differ; seeker and recruiter billing payloads are distinct. Their display helpers also operate on different amount units in places (`amount` vs `amountMinor`). The recruiter status styling recognizes `cancelled`; seeker styling does not.
- Seeker and recruiter message menus: separate response/API contracts and recruiter-only candidate search/composer workflow. Preserve each menu's keyboard and accessibility behavior.
- Admin vs owner company/user list managers: admin visibility and owner scoping are deliberately different.
- Seeker notifications vs admin notifications: separate payload and read-state contracts; admin read state is server-persisted while seeker read markers are browser-local.
- Backend compatibility aliases and repeated domain-specific validation are not candidates solely because handler bodies look similar; route order, status, validation, transaction, and quota behavior must remain identical.

## Validation Variants / Gaps Found (Not Changed)

- The two `safeStripeUrl` implementations have different hostname allowlists (C4); this is security-relevant and must not be silently normalized.
- Verified payment-method parsing differs on empty `brand` (C3). No choice was made between the current stricter and looser variants.
- Backend `docs/validation-inventory.md` records that the admin company-logo read path checks data-URL syntax/size but not file magic bytes, unlike stricter write paths; seeker/recruiter avatar paths also do not compare image magic bytes to declared MIME. These are existing validation gaps/variants, not permission to change validation during deduplication.
- The same backend inventory notes that invalid public `GET /jobs/:id` ObjectIds reach error middleware rather than an explicit route-level 400. Do not normalize its status/error during a helper extraction.
- Frontend `src/app/api/seeker/billing/route.ts` composes and sanitizes billing responses separately from role-scoped billing routes; retain its response shape and URL filtering. The backend remains authoritative for all limits and subscription state.
